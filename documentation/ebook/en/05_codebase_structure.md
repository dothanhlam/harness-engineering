# Chapter 5: Codebase Structure & Modules

To effectively work with the Harness Engineering repository, it's important to understand how the codebase is organized. The repository is divided into the modular orchestrator that powers the AI and the functional packages that the AI generates.

## The Orchestrator Core

### `main.go`
A slim entrypoint. It parses the `init` / `run` subcommands and their flags, loads configuration, applies CLI overrides, and hands off to the pipeline packages. The heavy lifting lives in `internal/`.

### `internal/` packages
The orchestrator was refactored from a single monolithic file into focused packages:

* **`internal/pipeline/`** — the core loops and state machine.
    * `core.go`: the sequential BA→Dev→QA→HITL→DevOps loop.
    * `epic.go`: the Epic Orchestrator (decompose a folder of requirements, run sub-tasks sequentially or in parallel).
    * `stages.go`: the pipeline `Stage` constants, `MaxRetries`, and the `WorkflowState` persisted to `workspace/state.json`.
    * `helpers.go`: prompt-building and generated-file parsing.
* **`internal/agent/`** — the pluggable agent adapter. Executes a local `llama_cpp` binary or a templated CLI agent (e.g. Claude) and parses token usage into telemetry.
* **`internal/config/`** — loads `harness_config.json`, merging it over built-in defaults.
* **`internal/qa/`** — the concurrent **security audit** (`AuditGeneratedCode`) and **test runner** (auto-detects Go / Node / Python).
* **`internal/memory/`** — updates and compacts `memory/system_blueprint.md`.
* **`internal/telemetry/`** — the mutex-protected execution metrics tracker.

The pipeline state is strictly tracked using the `WorkflowState` struct (`internal/pipeline/stages.go`), which gets dumped to `workspace/state.json` at every stage transition:
```go
// WorkflowState is the persisted pipeline state written to workspace/state.json.
type WorkflowState struct {
	TaskID       string    `json:"task_id"`
	CurrentStage Stage     `json:"current_stage"`
	RetryCount   int       `json:"retry_count"`
	UpdatedAt    time.Time `json:"updated_at"`
}
```

The security audit logic that prevents the AI from doing anything destructive lives in `internal/qa`, driven by the configurable rule set:
```go
// Each rule maps a forbidden substring to the audit failure it triggers.
if strings.Contains(code, pattern) {
	return fmt.Errorf("file %s %s", path, reason)
}
```

### `harness_config.json`
The global configuration file. It dictates which agents and models to use per phase (all `llama_cpp` by default), the context window, flash-attention, the `qa_ignore` list, and optional QA rule overrides.

## The AI's Environment

* **`.agents/`**: Contains the system prompts for our AI agents. For example, `antigravity_dev_prompt.md` instructs the Developer agent to emit surgical `SEARCH/REPLACE` blocks so it patches existing code instead of overwriting it.
* **`memory/`**: This is the "brain" of the AI. Unlike human engineers, AI agents lose their context between runs. We persist their memory here:
    * `definitions_of_done.md`: The strict technical checklist generated by the BA agent.
    * `system_blueprint.md`: An architectural map that helps the AI understand the broader system it is contributing to (updated and compacted by `internal/memory`).
    * `lessons_learned.md`: A living document of debugging guidelines and operational history.

## The Generated Workspace

* **`workspace/`**: This is the sandbox where all AI-generated code is placed. Each feature gets its own clean subfolder — for example `password/` (bcrypt hashing), `email_validation/`, `landing_page/`, `random/`, and `fibonacci/`. It also holds `state.json` (the live pipeline stage) and `RELEASE_NOTES.md`.
* **`telemetry.json`** (written to the project root at the end of every successful run):
      ```go
      type Telemetry struct {
          TotalDurationSeconds float64  `json:"total_duration_seconds"`
          StagesExecuted       []string `json:"stages_executed"`
          TotalRetriesUsed     int      `json:"total_retries_used"`
          CodeHealingSuccess   bool     `json:"code_healing_success"`
          LinesOfCodeGenerated int      `json:"lines_of_code_generated"`
          Timestamp            string   `json:"timestamp"`
      }
      ```

By keeping the orchestrator (`main.go` + `internal/`) strictly separated from the generated code (`workspace/`), we ensure that our AI can build modular, testable software without ever breaking the core pipeline itself.
